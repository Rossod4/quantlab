## Design decisions / deviations
- `AccountSnapshot`/`BrokerCapabilities`/`OrderAck` are NEW types in
  `paper/broker.py`, not `core/types.py` (packet only named `Order`/`Fill`/
  `Position`/`PortfolioSnapshot` as existing interfaces to reuse).
- `client_order_id = f"{strategy_id[:12]}-{asof:%Y%m%d}-{ticker}"` is
  generated by `rebalancer.plan_orders` (shared via `broker.
  client_order_id_for`), not per-broker - a rerun of the same day's plan is
  idempotent at ANY broker via its own dedup, not just Alpaca.
- Actions-cache refresh policy (QUANT-NOTES M02b/M04): `runner._generate_
  targets_with_actions_refresh` catches `StaleActionsCacheError` on the
  first `generate_targets` attempt, refreshes the strategy's WHOLE declared
  universe (packet says "for the universe", not just the offending ticker),
  logs the refreshed list, retries once.
- Promotion gate `find_promoting_report_card` `rglob`s `reports_dir` for
  `report_card.json` (no fixed path - `validate --full` writes wherever
  `--out` points) matching `strategy_id` + `DATA_SEMANTICS_VERSION` +
  verdict `ELIGIBLE_FOR_PAPER`; picks the most-recently-modified match.
- `resolve_asof` defaults to `prev_trading_day(today)` unconditionally (no
  intraday clock to know if "today" closed) AND clamps to the price cache's
  actual last bar for the benchmark - canary (k) pins this, mutation-checked
  (below). Reconcile compares `account_before` against the prior
  NON-REFUSED journal entry's `account_after`.
- Did NOT run `quantlab paper run --broker mock --dry-run` against the real
  `configs/platform.yaml` (shared `data/cache` junction, read-only for me) -
  a cold ticker could trigger a live fetch+write there. Verified the
  identical path with fake providers instead (`tests/test_cli_paper.py`).
